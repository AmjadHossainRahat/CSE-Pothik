## Contributing

1. Read [DESIGN.md](../../DESIGN.md), [SKILL.md](../../SKILL.md) and [AI-Prompt.md](../../AI-Prompt.md).
2. Update content, relationships, tests and documentation together.
3. Preserve English/Bangla, light/dark and mobile/desktop parity.
4. Run the complete relevant quality cycle from the [engineering guide](../engineering/README.md#quality-and-testing).
5. Inspect the rendered result before publishing.

Contributions should keep student-facing guidance free, practical, accessible and honest.

## Fork and pull-request workflow

External contributors should fork the public repository, create a focused branch in that fork and propose the change through a pull request to `AmjadHossainRahat/CSE-Pothik:main`. They do not need direct write or deployment access.

The root [CONTRIBUTING.md](../../CONTRIBUTING.md) provides the complete beginner-friendly procedure: prerequisites, fork and remote setup, branch synchronization, Yarn installation, content expectations, validation commands, commit preparation, pull-request endpoints, review updates and post-merge cleanup. It also explains the maintainer's quality and deployment boundary.

## Feedback

Every page contains a quiet invitation to use the voluntary [CSE-Pothik feedback form](https://forms.gle/ZKyHbR9MHoebFbnWA). It opens in a new tab instead of interrupting reading with a popup, embed or floating control. Form responses and free text are not sent to GA4.
